# 《未署名的守卫》剧情与实现说明

> 文档用途：记录求职 Demo 的剧情内容、玩家流程和 Unity 实现方式。  
> 当前场景：`Assets/Scenes/GameScene/Demo 1.unity`  
> 内容体量：1 名 NPC、1 名主角、1 个石头人、2 条短任务。

## 1. 剧情定位

《未署名的守卫》是一段冷峻、偏考古悬疑的西方奇幻故事开头。它不讲述骑士拯救村庄或讨伐邪恶怪物，而是让玩家调查一处被后人错误解释的地下遗址。

城邦一直将遗址称作“古代刑场”，但遗址中的石头人并非刽子手。它是一名不会说话的守卫，也是一份仍然存活的历史证据。玩家最终取得的封印铭片只能证明官方说法存在问题，却不能解释是谁篡改了历史、铭片上被抹去的名字属于谁。

Demo 在真相刚刚显露时结束，不需要补完完整世界观。留白既符合技术展示项目的体量，也为后续扩展保留空间。

## 2. 主要角色

### 骑士

玩家控制的主角。身穿盔甲，受命进入遗址调查。骑士没有长篇背景介绍，也不承担大量自言自语；玩家通过探索、战斗和少量回答表达角色立场。

### 记录员

唯一需要对话的 NPC。他已经进入过遗址外围，但不敢接近苏醒的石头守卫。记录员的作用是提供调查目标、接收证物，并在结尾点出悬念。

### 石头守卫

现有石头人敌人。它没有对白，也不需要人格化演出。它的敌对行为、所在的仪式间和死亡后留下的铭片共同完成叙事。

## 3. 开场文字

玩家从开始菜单进入 `Demo 1` 后，首次显示以下全屏文字：

> 城邦将这座遗址称作刑场。
>
> 但失联的记录员在最后一封报告中写道：
>
> “石头没有审判任何人。它只记得，谁下令遗忘。”

玩家点击“继续”关闭文字。观看状态保存到 `PlayerPrefs`，同一设备之后进入场景不会重复强制显示。

## 4. 完整游戏流程

### 4.1 接取任务“遗失的页码”

玩家在入口附近找到记录员并开始对话。

记录员：

> 我只找到一页残稿。深处的石头守卫不让任何人靠近。

玩家选择：

> 我去取回记录。

任务“遗失的页码”进入 `Active` 状态。记录员补充：

> 不要相信墙上的判词。它们比灰尘新。

HUD 显示：

- 任务：遗失的页码
- 目标：查找无署名记录页

### 4.2 找到无署名记录页

玩家前往实验室或水晶洞方向，在残破工作台附近找到“无署名记录页”。按交互键取得记录页后，任务进入 `ReadyToTurnIn` 状态。

HUD 改为：

- 任务：遗失的页码
- 目标：返回记录员处交付

记录页不需要弹出长篇阅读界面。它的核心信息通过玩家回报时的回答体现：

> 记录页提到仪式间。

选择该回答后，第一条任务完成，第二条任务“守卫的证词”立即开始。

记录员：

> 去仪式间。石头守卫醒着，你得先让它停下。

### 4.3 完成任务“守卫的证词”

HUD 依次显示两个顺序目标：

1. 击败石头守卫。
2. 取得封印铭片。

玩家必须先击败仪式间中的石头守卫。提前接近封印铭片不会推进任务，也不会消耗交互物。

石头守卫死亡后，玩家与其附近的“封印铭片”交互。第二条任务进入 `ReadyToTurnIn` 状态，HUD 提示返回记录员处交付。

### 4.4 Demo 结尾

玩家再次与记录员交谈，选择：

> 交出封印铭片。

任务完成。记录员说出最后一句：

> 它守着的不是门，是一个不该被留下的名字。

故事在这里结束。玩家已经确认遗址并非刑场，但尚不知道被抹去的名字、石头守卫真正保护的对象，以及城邦为何篡改记录。

## 5. 任务数据设计

任务使用 `QuestDefinition` 保存静态配置，使用 `QuestService` 保存运行时状态。任务配置位于 `Assets/Resources/Quests`，运行时通过 `Resources.LoadAll<QuestDefinition>("Quests")` 加载。

任务状态依次为：

```text
Available -> Active -> ReadyToTurnIn -> Completed
```

### 5.1 稳定 ID

| 内容 | 稳定 ID |
|---|---|
| 遗失的页码 | `unsigned_guardian.lost_page` |
| 守卫的证词 | `unsigned_guardian.guardian_testimony` |
| 无署名记录页 | `unsigned_guardian.record_page` |
| 石头守卫 | `unsigned_guardian.stone_golem` |
| 封印铭片 | `unsigned_guardian.sealing_inscription` |

这些 ID 同时用于任务资产、对话动作、场景上报器和存档。不要使用场景对象名称作为运行时判断条件，也不要随意修改已经用于存档的 ID。

### 5.2 任务目标

“遗失的页码”包含一个交互目标：

```text
Interaction: unsigned_guardian.record_page
```

“守卫的证词”包含两个必须按顺序完成的目标：

```text
EnemyKilled: unsigned_guardian.stone_golem
Interaction: unsigned_guardian.sealing_inscription
```

`QuestWorldReporter` 将场景交互和敌人死亡转换为任务事件。事件只有在匹配当前 `Active` 任务的当前目标时才会成功，因而提前探索不会破坏任务流程。

### 5.3 存档

`QuestService` 使用 `PlayerPrefs` 保存任务状态和当前目标索引，键名为：

```text
LowPolyGame.QuestProgress
```

重复开始、重复提交和重复上报同一目标都不会再次产生进度。任务配置资产只保存静态定义，不保存运行时状态。

## 6. 对话系统实现

记录员使用可重复进入的 `Dialogue_UnsignedGuardian.asset`。每次交互都从入口节点重新计算选项条件，而不是在首次对话后永久播放固定完成文本。

入口节点包含三个互斥选项：

| 玩家选项 | 显示条件 | 执行动作 |
|---|---|---|
| 我去取回记录。 | `lost_page == Available` | `StartQuest(lost_page)` |
| 记录页提到仪式间。 | `lost_page == ReadyToTurnIn` | 提交第一任务并开始第二任务 |
| 交出封印铭片。 | `guardian_testimony == ReadyToTurnIn` | 提交第二任务 |

对话节点和选项均支持：

- 所需任务 ID。
- 所需任务状态。
- 开始任务、推进目标和提交任务动作。
- 原有 `EventId`，继续用于演出、音效或兼容事件，不作为任务状态的数据源。

在 Unity 中打开 `工具 > 对话编辑器` 可以编辑以上字段。点击“校验对话”会检查空文本、无效跳转、不可达节点、循环、缺失任务 ID、无效任务引用，以及推进动作缺少目标 ID等问题。

## 7. 场景实现

### 7.1 场景入口

开始菜单的 `StartMenuController.targetScenePath` 指向：

```text
Assets/Scenes/GameScene/Demo 1.unity
```

`Demo 1` 已加入 `EditorBuildSettings`，因此从开始菜单可以直接进入剧情场景。

### 7.2 记录员

场景对象 `NPC_1` 挂载 `NpcDialogueInteractor`，并引用 `Dialogue_UnsignedGuardian.asset`。玩家进入交互范围后按 `E` 或手柄南键开始对话。

### 7.3 任务物与石头守卫

当前场景包含：

- “无署名记录页”：交互事件上报器。
- “未署名的守卫”：由现有 `StoneGolem.prefab` 实例化，死亡时上报敌人目标。
- “封印铭片”：交互事件上报器。

目前记录页与铭片使用简单方块作为占位物。正式展示前应替换其网格、材质和摆放位置，但必须保留 `QuestWorldReporter` 及稳定 `targetId`。

建议最终布置：

- 把记录页放在 `Laboratory` 或 `Crystal_Caves` 的残破桌面上。
- 把石头守卫放在 `Ritual` 的主要战斗空间，并确认 NavMesh 可达。
- 把铭片放在石头守卫倒下后玩家容易发现的位置，可增加微弱发光或粒子提示。

### 7.4 开场和 HUD

`UnsignedGuardianUiBootstrap` 只在 `Demo 1` 中创建剧情 UI：

- 全屏开场文字。
- “继续”按钮。
- 屏幕右上角的当前任务标题与目标。

这套 UI 由运行时代码创建，不要求每次手工修改场景。后续如果改为正式 UGUI Prefab，应保留 `OpeningNarrative` 和 `QuestHud` 的职责边界。

## 8. 一键安装与重新生成

Unity 菜单提供：

```text
工具 > 未署名的守卫 > 安装剧情内容
```

该命令会：

1. 创建或更新两条任务资产。
2. 创建或更新记录员对话资产。
3. 给 `NPC_1` 绑定记录员对话。
4. 创建记录页和封印铭片交互物。
5. 在场景缺少石头人时实例化现有石头人预制体。
6. 给石头人配置死亡任务上报器。
7. 将 `Demo 1` 加入 Build Settings。

安装器可重复执行，但执行前仍应保存并检查场景中的手工美术调整。安装器生成的占位物位置只用于保证任务可运行，最终位置应由关卡设计确认。

## 9. 验收清单

- 新存档进入 `Demo 1` 时显示开场文字。
- 记录员只在第一任务可接取时显示“我去取回记录”。
- 未接任务时与记录页交互不会让它消失。
- 取得记录页后 HUD 提示返回交付。
- 提交第一任务后自动开始“守卫的证词”。
- 未击败石头守卫时，铭片不能推进任务。
- 击败石头守卫后，取得铭片会进入待交付状态。
- 最终交付后不会重复完成或重复发放进度。
- 重启游戏后任务状态和目标索引保持正确。
- 键鼠和手柄均可开始对话及完成交互。

现有 EditMode 测试 `QuestServiceEditModeTests` 覆盖两条任务的顺序、提前交互和重复调用行为。

## 10. 后续可选扩展

如果 Demo 仍有开发时间，优先补充表现，不扩大剧情体量：

1. 为记录页和铭片制作可识别的小型模型与发光材质。
2. 在石头守卫死亡后播放镜头震动、尘土和铭片显现效果。
3. 为任务交互物增加统一的靠近提示。
4. 在结尾淡出画面并显示项目标题，明确 Demo 到此结束。

不建议为本段剧情新增更多 NPC、长篇对话、完整编年史或新的大型场景。当前故事的价值在于用少量内容串起对话、任务、交互、战斗、UI 和存档的完整技术闭环。
