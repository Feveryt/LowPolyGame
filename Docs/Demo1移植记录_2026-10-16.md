# Demo 1 主场景移植记录（2026-10-16）

主游戏场景：`Assets/Scenes/GameScene/Demo 1.unity`。

## 生效方式

Demo 1 的玩家、石头人、龙和 UIManager 已引用本轮更新的共享预制体。逐项检查场景覆盖后确认，武器、Enemy 行为、Boss 血条及相机修复均能直接继承，无需另建一套场景专用组件。

| 内容 | Demo 1 中的来源和结果 |
| --- | --- |
| 武器握持及剑刃方向 | Player 预制体、PlayerOutfit、共享装备定义和 Player.controller；9 件武器装备、收回及再次拔出检查通过 |
| Enemy 攻击表现 | 场景原有 StoneGolem / DragonBoss 继承更新的攻击脚本；普通拳击、撕咬的预警在实测中出现 |
| 攻击中受伤 | 两个场景 Enemy 攻击中均正常扣血，不置入待播放受击请求，攻击结束后也不补播受击动画 |
| Boss 血条 | EnemyBossHealthTarget + UIManager 自动创建 EnemyBossHealthCanvas；单敌一条、双敌两条，名称在槽下方且两行互不重叠，血量绑定正确 |
| 第三人称相机 | 共享 CameraModeController 保留热保存还原逻辑；Demo 1 使用自身原有轨道半径 2.8 / 4 / 2.8 米，结束运行后磁盘配置保持原值 |

## 本次补改

`Assets/Resources/Prefabs/UI/StartMenuCanvas.prefab` 的开始游戏入口原先指向 TestAct。本次同时将编辑器场景资源引用和构建用路径改为 Demo 1，避免点击开始后仍进入测试场。

GameStart 场景通过预制体继承了新入口，无旧场景覆盖。构建设置已启用 Demo 1。

## 实机验证

1. 直接启动真实 Demo 1，使用场景内现有玩家与两个 Enemy 测试，未以另行实例化的测试敌人代替。
2. 逐一检查装备 2000–2008 的手部位置、配置朝向、收回、再次拔出及命中盒。
3. 在 Play 内临时将两个敌人移近，检查单敌/双敌血条、行间隔、名称和真实血量更新；运行时位置改动退出后撤销。
4. 对实际拳击、撕咬过程中施加伤害，持续观察至攻击结束之后，确认只扣血、无即时或延迟受击动画。
5. 从 GameStart 调用实际开始按钮，确认异步进入 `Assets/Scenes/GameScene/Demo 1.unity`，自动生成一套 Boss HUD，并找到两个场景敌人。
6. 退出 Play 后恢复测试前存档和原 Play 启动场景设置。TestAct 原有未保存编辑仍保留，没有保存或重载覆盖它。

## 既有动画限制

移植沿用当前武器修正，不新增动画资产。`Attack_06` 的手腕运动方向与其他攻击不同，固定握持角度仍无法使其所有挥砍阶段完全以剑刃迎敌；这是已有动画限制，详见《武器握持修正_2026-10-16.md》的“刃面修正”记录。
