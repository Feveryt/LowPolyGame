# 持剑绑定规范与防回退说明

记录日期：2026-10-22。适用项目：LowPolyGame。主游戏场景：`Assets/Scenes/GameScene/Demo 1.unity`。

本文说明之前如何修正持剑位置、最终配置应是什么，以及后续 Agent 必须保护哪些数据。仓库根目录 `AGENTS.md` 提供常驻入口。

## 1. 用户确认的效果

- 角色右手在攻击姿势下会形成握持缝隙，剑柄应沿该缝隙穿过，随右手骨骼运动。
- 握持位置正确后，还要校正剑身绕柄轴的旋转，使主要挥砍动作以锋刃迎敌，而不是宽剑面拍打。
- 不通过重做全部攻击动画或临时逐帧扭转武器来掩盖错误的装备坐标。

## 2. 2026-10-22 检查与恢复状态

2026-10-22 编写本文时，实际读取九个 `Equip_2000_Weapon.asset` 至 `Equip_2008_Weapon.asset`，发现磁盘上的 `equipmentEuler` 全部又是旧值 `(-90, 90, 0)`；位置仍为 `(9, 3.6, 0)`，缩放仍为 `100`。

随后用户明确要求恢复九件武器，已将这九个资源的 `equipmentEuler` 按第 3 节基准恢复。位置 `(9, 3.6, 0)`、缩放 `100` 以及其他物品字段保持原值。恢复直接作用于共享物品定义，Demo 1 的正常装备和拔剑流程会读取这些参数。本轮只做资源恢复和文件核对，没有重新执行 Play 动画测试；此前修正过程和验证记录见文末链接。

检查还发现一个确定存在的覆盖入口：`Assets/Editor/EquipmentIconGenerator.cs` 的 `CreateOrUpdateItem` 不论物品是否已存在，都会写入位置、旋转、缩放并保存。恢复资源时，已同步修正生成器九件武器的角度，并纠正“只补图标”的过时注释，防止后续生成操作再次写回旧值。本次没有操作历史证明生成器触发了发现时的回退。

## 3. 正确配置基准

资源目录：`Assets/GameData/Definitions/Items/`。下列字段来自 `ItemDefinition`，全部是相对右手 `Hand_R` 的局部值，不是世界坐标。

| 资源文件 | 名称 | equipmentPosition | equipmentEuler（度） | equipmentScale |
| --- | --- | --- | --- | --- |
| `Equip_2000_Weapon.asset` | 水晶长剑 | `(9, 3.6, 0)` | `(0, 90, -90)` | `100` |
| `Equip_2001_Weapon.asset` | 巨剑（直刃） | `(9, 3.6, 0)` | `(90, 0, 180)` | `100` |
| `Equip_2002_Weapon.asset` | 华丽之剑 | `(9, 3.6, 0)` | `(0, 90, -90)` | `100` |
| `Equip_2003_Weapon.asset` | 弯刀 | `(9, 3.6, 0)` | `(0, 90, -90)` | `100` |
| `Equip_2004_Weapon.asset` | 手斧 | `(9, 3.6, 0)` | `(0, 90, -90)` | `100` |
| `Equip_2005_Weapon.asset` | 短锤 | `(9, 3.6, 0)` | `(-90, 0, 0)` | `100` |

Unity 可以用等价欧拉角表示同一旋转，程序检查时应比较 Quaternion 或变换后的轴，不能只比较 Inspector 显示字符串。资源维护时优先保留表中的规范写法，便于审阅。

## 4. 之前是怎样修正的

### 4.1 保留握持位置，修正穿过手指的方向

旧旋转 `Quaternion.Euler(-90, 90, 0)` 将武器模型的本地 `+Y` 长轴转到 `Hand_R` 的本地 `-X`，导致剑柄横穿握持孔。此前在实际攻击姿势下检查弯曲后的指骨和手部网格，确认柄应沿手部 Z 方向穿过握持缝隙，剑刃从拇指/食指一侧的 `-Z` 伸出。

位置 `(9, 3.6, 0)` 已在握持孔内，因此没有继续把位置挪到所谓“拇指与食指根部中点”，而是调整旋转，使以下关系成立：

```csharp
Quaternion.Euler(item.EquipmentEuler) * Vector3.up
// 相对于 Hand_R，应约等于 Vector3.back，即 (0, 0, -1)。
```

这里的 `+Y` 是模型长轴，`-Z` 是右手局部轴，不能替换成角色固定世界前方。手会随动画转动，武器也应跟着转。

此前错误试验用“武器本地 Y=0.1”为柄中心去拟合手心，得到位置 `(6.96, -9.61, -3.59)`；这个采样点实际上可能已在护手区域。该试验值已弃用，不要从旧交接记录恢复它。

### 4.2 保持柄的位置和长轴，再校正刃面

用户确认握持位置正确后，指出剑刃横着、挥砍成了宽剑面迎敌。因此，对 2000、2001、2002、2003、2004、2008 在第一轮正确握持姿态上，绕武器自身的本地 Y 轴额外旋转 +90°：

```csharp
Quaternion finalRotation = firstPassRotation * Quaternion.AngleAxis(90f, Vector3.up);
```

这是解释历史修正的运算，**不要在最终配置上每次装备时再叠加一次**。局部旋转的乘法顺序有意义，也不能直接把 Inspector 的 Y 加 90 当作相同操作。表中已包含最终结果。

直刃巨剑与其他剑、刀的模型宽轴不同，因此 2001 的欧拉角单独配置；不能把九件武器统一成同一旋转。短锤、长矛、法杖保持第一轮长轴修正。

### 4.3 为什么局部缩放是 100

此前检查的角色骨骼世界缩放约为 `0.01`，挂在其下的武器用 `localScale=(100,100,100)` 补偿，武器最终世界缩放约为 `(1,1,1)`。位置也是手骨局部单位，`9` 不表示世界中横移 9 米。不要将局部缩放改为 1，或只改模型导入缩放去“统一单位”。

## 5. 真正生效的数据链

| 位置 | 职责与保护点 |
| --- | --- |
| `Assets/Scripts/Data/ItemDefinition.cs` | 声明 `equipmentPosition`、`equipmentEuler`、`equipmentScale` 以及对应读取属性 |
| 九个 `Equip_200*_Weapon.asset` | 当前装备实际读取的持握参数；运行时的主要配置来源 |
| `Assets/Scripts/Gameplay/Character/Player/PlayerOutfit.cs` | `EquipAt` 创建实例；`AttachWeaponToSocket` 处理手部/背部搬运；`ApplySocketTransform` 应用局部变换 |
| `Assets/Resources/Prefabs/Player/Player.prefab` | 玩家共享预制体，保存默认武器、背挂引用、切换时机等 |
| `Assets/Scenes/GameScene/Demo 1.unity` | 主场景；检查玩家实例的覆盖及引用，避免另建一套持握参数 |
| `Assets/ArtRes/Animator/Player.controller` | 当前玩家使用的控制器；不要误改另一份同名旧控制器 |
| `Assets/Editor/EquipmentIconGenerator.cs` | 生成器也会重写已有资源的挂点配置，是需要检查的回退入口 |

手持时 `ApplySocketTransform` 的核心逻辑是：

```csharp
instance.localScale = Vector3.one * item.EquipmentScale;
instance.localPosition = item.EquipmentPosition;
instance.localRotation = Quaternion.Euler(item.EquipmentEuler);
```

因此只在编辑器 Hierarchy 中移动初始剑，或只在 Play 中修改实例 Transform，不会修复物品定义；换装或再次拔剑时会重新应用资源参数。这也是 Demo 1 编辑模式看起来正常、运行后又变反时必须先查物品资产的原因。

## 6. 不要混淆背挂、盾牌和命中盒

- 战斗时武器挂在 `Hand_R`；收剑时挂在 `Root/Hips/Spine_01/Spine_02/SM_Item_Sword`。背挂旋转与手持旋转分别维护。
- 当前玩家预制体：`sheathLocalPosition=(0,0,0)`、`sheathLocalEuler=(0,0,140)`、`autoAlignSheathToDecoration=true`。
- 拔剑时长 `0.8`、搬运比例 `0.35`；收剑时长 `0.867`、搬运比例 `0.45`。不要为摆正手上剑而改这些时机。
- 背挂用真实 `Renderer.bounds` 的世界包围盒中心对齐；不要换成 `localBounds × lossyScale`，历史上这会造成约半米的对齐偏差。
- 盾牌挂 `Hand_L`，当前盾牌位置 `(0,0,0)`、角度 `(0,180,0)`；不要把武器参数批量应用到盾牌。
- `Hand_R/WeaponHitboxZone` 根据真实武器实例包围盒适配。模型位置错误不能通过移动命中盒或放大攻击范围来掩盖。

## 7. 后续 Agent 的维护规则

1. 与持握无关的功能开发保留上述参数、挂点、骨骼和攻击动画。不要通过全量重建玩家预制体或批量重置场景覆盖来处理无关问题。
2. 运行 `Tools/Combat/8. Generate Equipment Icons + Items` 前，核对生成器角度仍与本表一致。此工具会重写已有物品的字段，并非只更新图标。
3. 维护生成器时，保持九件武器定义与本表匹配的模型基准一致；只改九件资产而不检查生成器，后续仍可能被覆盖。
4. 修改装备加载、初始武器、换装、收拔剑或共享玩家预制体时，同时检查九件资产的差异。不得将旧角度重新作为“默认值”。
5. 发生回退时，先记录磁盘值、运行时值和写入入口。恢复参数只处理相关字段，保留资源 GUID、其他物品数据及用户未提交修改；不得用整文件 `git restore` 覆盖其他工作。
6. 用户以后明确要求更换模型、角色骨架或持握设计时，可以重新校准；同步更新本文和根目录 `AGENTS.md`，记录适用模型与验证结果。

## 8. 修改后怎样验收

以下为后续绑定变更的验收步骤，不表示本次文档任务重新执行了 Play 测试：

1. 在真实 Demo 1 中使用场景现有玩家，先测试初始水晶长剑的正常拔剑，不先调用额外 `Equip` 掩盖初始化问题。
2. 检查 `Hand_R` 下武器实例：局部位置/旋转/缩放对应本表；长轴沿手部 `-Z`，柄穿过握持缝隙，世界缩放约为 1。
3. 使用游戏相机和手部特写观察待机、防御、轻攻击与重攻击，尤其在 `AttackHit` 到 `AttackHitEnd` 伤害窗口检查刃口方向。不要仅凭一个视角或一个静止姿势判断。
4. 对九件武器分别完成换装、收回、再次拔出；手持参数不能回退，背挂不能飘到头顶，命中盒应跟随真实实例。
5. 验证后退出 Play，恢复测试前存档与启动设置。测试前备份 `RPG.Save.SingleSlot`；对原本已有未保存修改的场景，不直接保存、重载或切换覆盖。
6. 最后检查 diff，确认无关的骨骼、动画、盾牌、场景覆盖或其他 Agent 修改没有被改动。

**已有动画限制**：`Attack_06` 的手腕运动方向不同，固定挂载角度不能使它与其他五段攻击的所有阶段同时完全对齐。不要为了单独修正这一段，重新改坏九件武器通用配置。如需处理，应作为该动画的专项调整，并重新验证其他攻击。
