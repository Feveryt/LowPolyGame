# 《灰烬中的档案》任务设计与实现

> 生成时间：2026-10-22
> 定位：《未署名的守卫》之后新增的第二段战斗任务，结构完全复用「守卫的证词」。
> 场景：`Assets/Scenes/GameScene/Demo 1.unity`

---

## 1. 设计依据：先拆解「守卫的证词」

| 维度 | 石头人任务的做法 |
|---|---|
| 静态配置 | `QuestDefinition`（ScriptableObject），放在 `Assets/Resources/Quests/`，由 `QuestService` 用 `Resources.LoadAll` 加载 |
| 运行时状态 | `QuestService` + `PlayerPrefs`，状态机 `Available → Active → ReadyToTurnIn → Completed` |
| 目标类型 | `QuestObjectiveType.EnemyKilled`（击杀）+ `QuestObjectiveType.Interaction`（交互） |
| 稳定 ID | 点分命名 `unsigned_guardian.*`，同时被任务资产、对话动作、世界上报器和存档引用 |
| 世界事件 | `QuestWorldReporter` 挂在敌人/交互物上，把"死亡"或"按 E 交互"转换成 `QuestService.NotifyEnemyKilled / NotifyInteraction` |
| 顺序保护 | `QuestWorldReporter` 只在 `NotifyInteraction/NotifyEnemyKilled` 返回 `true` 时才 `consumed = true` 并隐藏自身；提前交互不会推进任务也不会消耗物件 |
| 对话 | `DialogueAsset` 由 `DialogueEditorWindow`（工具 > 对话编辑器）编辑，节点/选项带 `requiredQuestId + requiredQuestState` 和 `questActions` |
| NPC | `NPC_1` 挂 `NpcDialogueInteractor`，引用对话资产；对话 `repeatable = true`，每次交互从入口节点重算条件 |

「守卫的证词」的目标序列就是标准范式：

```text
EnemyKilled: unsigned_guardian.stone_golem        → 击败石头守卫
Interaction: unsigned_guardian.sealing_inscription → 取得封印铭片
```

新任务只把这两个 `targetId` 换成龙的，其余结构一比一复用。

---

## 2. 世界观衔接

原剧情结尾是记录员那句：

> 它守着的不是门，是一个不该被留下的名字。

新任务不解释这个名字，而是抛出**第二层悬念**：篡改不是过去的事，而是**正在进行**。

设定上的关键点是：**那条龙不是在守宝，它在烧档案**。它和石头守卫构成一组对照——

- 石头守卫：不会说话，但**记得**；
- 巨龙：会喷火，专门**抹去记得的东西**。

这样既解释了"为什么最深处的敌人是龙"，也没有把世界观从"考古悬疑"改写成"屠龙史诗"。玩家打赢之后拿到的不是宝物，而是**半页没烧完的纸**，这个落点与原作的冷峻调性一致。

## 3. 新任务结构

### 3.1 任务资产

`Assets/Resources/Quests/Quest_unsigned_guardian_ember_archive.asset`

```yaml
questId:     unsigned_guardian.ember_archive
title:       灰烬中的档案
description: 击败盘踞在灰烬厅的巨龙，取回它没能烧尽的残页。
objectives:
  - objectiveId: unsigned_guardian.ember_archive.objective_1
    type:        EnemyKilled
    text:        击败焚书的巨龙
    targetId:    unsigned_guardian.dragon_boss
    requiredCount: 1
  - objectiveId: unsigned_guardian.ember_archive.objective_2
    type:        Interaction
    text:        取得未烧尽的残页
    targetId:    unsigned_guardian.half_burnt_archive
    requiredCount: 1
```

### 3.2 稳定 ID 扩展

在 `UnsignedGuardianQuestIds` 中新增：

| 常量 | 值 |
|---|---|
| `EmberArchive` | `unsigned_guardian.ember_archive` |
| `DragonBoss` | `unsigned_guardian.dragon_boss` |
| `HalfBurntArchive` | `unsigned_guardian.half_burnt_archive` |

> 与既有约定一致：**不要**用场景对象名称做运行时判断，这些 ID 同时被存档引用。

## 4. 对话流程

对话仍然写在 `Assets/GameData/Definitions/Dialogue/Dialogue_UnsignedGuardian.asset` ——
**同一位记录员，不新增 NPC**（与文档"不建议新增更多 NPC"一致）。

节点从 4 个扩展到 7 个：

| 节点 | 内容 | 选项 |
|---|---|---|
| 1 | 我只找到一页残稿。深处的石头守卫不让任何人靠近。 | 4 个（新增第 4 个，见下） |
| 2 | 不要相信墙上的判词。它们比灰尘新。 | — |
| 3 | 去仪式间。石头守卫醒着，你得先让它停下。 | — |
| 4 | 它守着的不是门，是一个不该被留下的名字。 | **新增**「深处好像还有烟。」 |
| **5（新）** | 烟是今天才起来的。灰烬厅里那条龙，烧的不是柴。 | **新增**「我去截住它。」 |
| **6（新）** | 别让它把最后半页也烧了。灰烬不会说谎，字会。 | — |
| **7（新）** | 这不是旧事。有人还在继续抹。 | — |

### 4.1 条件与动作

| 选项 | 出现条件 | 跳转 | 任务动作 |
|---|---|---|---|
| 我去取回记录。 | `lost_page == Available` | 2 | `StartQuest(lost_page)` |
| 记录页提到仪式间。 | `lost_page == ReadyToTurnIn` | 3 | `SubmitQuest(lost_page)` + `StartQuest(guardian_testimony)` |
| 交出封印铭片。 | `guardian_testimony == ReadyToTurnIn` | 4 | `SubmitQuest(guardian_testimony)` |
| **我找到了没烧完的那页。** | `ember_archive == ReadyToTurnIn` | 7 | `SubmitQuest(ember_archive)` |
| **深处好像还有烟。** | `ember_archive == Available` | 5 | — |
| **我去截住它。** | `ember_archive == Available` | 6 | `StartQuest(ember_archive)` |

### 4.2 流程

```text
交出封印铭片
   ↓ 节点 4（它在守护一个名字）
   ↓ 选项「深处好像还有烟。」
节点 5（龙在烧档案）
   ↓ 选项「我去截住它。」→ StartQuest(ember_archive)
节点 6（别让它把最后半页也烧了）
   ↓ 对话结束，HUD 显示：击败焚书的巨龙

[击败龙] → [按 E 取残页] → ReadyToTurnIn
   ↓ 回到记录员，选项「我找到了没烧完的那页。」
节点 7（这不是旧事。有人还在继续抹。）→ Demo 结束
```

> 节点 4 在玩家尚不满足 `ember_archive == Available` 时不会显示新选项，
> 此时点"继续"会走 `NextNodeId < 0` → `CompleteDialogue()`，不会卡死。

## 5. 场景实现

| 对象 | 变更 |
|---|---|
| `DragonBoss` | 新增 `QuestWorldReporter`：`targetId = unsigned_guardian.dragon_boss`，`eventType = EnemyKilled` |
| `未烧尽的残页` | **新建**，由「封印铭片」复制而来（MeshFilter + BoxCollider + MeshRenderer + QuestWorldReporter），缩放 `(0.42, 0.02, 0.55)` 呈薄片状，放在龙身后的地面上 |
| `UnsignedGuardianBindings` | 新增 `halfBurntArchive` / `dragonReporter` 两个可选字段，**但 Demo 1 场景当前并未挂该组件**（现有铭片也是常驻可见的），所以残页与铭片一样保持常驻可见 |

> **为什么残页常驻可见也安全**：`QuestWorldReporter.TryInteract` 只有在
> `QuestService.NotifyInteraction(targetId)` 返回 `true` 时才隐藏自己；
> 而后者只在该 `targetId` 是**当前 Active 任务的当前目标**时返回 `true`。
> 提前交互既不会推进任务，也不会消耗物件 —— 与「未击败石头守卫时铭片不能推进任务」的规则完全一致。

残页位置：`(-0.99, 5.21, -48.43)`（龙 `(-2.59, 5.16, -51.63)` 身后约 3.4m）。

## 6. 与既有设计的一致性

| 约束 | 新任务的遵循方式 |
|---|---|
| 一任务一资产、一资产一 `questId` | `Quest_unsigned_guardian_ember_archive.asset` |
| 目标必须顺序完成 | `EnemyKilled` 在前、`Interaction` 在后，`QuestService` 只推进当前目标 |
| 不新增 NPC | 复用 `NPC_1` 记录员与同一份 `DialogueAsset` |
| 对话可重复进入、按条件重算 | 继承 `repeatable = true`，新选项全部带任务状态条件 |
| 稳定 ID 不做运行时名称判断 | 全部使用 `UnsignedGuardianQuestIds` 常量 |
| 存档兼容 | 新任务只是多一条 `QuestProgressEntry`，旧存档读取时按 `Available` 处理 |
| 不扩大剧情体量 | 只加 3 个节点、2 个目标、1 个场景物件 |

## 7. 对话在哪里编辑

**位置**：`Assets/GameData/Definitions/Dialogue/Dialogue_UnsignedGuardian.asset`

**编辑入口（Unity 编辑器）**：

```text
菜单栏 → 工具 → 对话编辑器
```

在窗口中选择 `Dialogue_UnsignedGuardian` 后可以：

- 编辑 NPC 名称与头像（当前 `npcName = 记录员`，头像为空）
- 增删节点、改台词、设置 `nextNodeId`
- 为节点/选项设置 `requiredQuestId` + `requiredQuestState`
- 为选项配置 `questActions`：`StartQuest` / `AdvanceObjective` / `SubmitQuest` / `OpenShop`
- 点击 **「校验对话」** 检查空文本、无效跳转、不可达节点、循环、缺失任务 ID 等

场景侧绑定：`NPC_1` 上的 `NpcDialogueInteractor` 引用这份资产，玩家靠近按 `E`（或手柄南键）触发。
