> 另有一个 `ArtRes/Animation/Player/Player.controller` —— **是旧版，Player.prefab 没用它**。

原本控制器里 `Eqip_To_Uneqip` 状态**存在但未接线**，且**没有拔剑状态**，只靠 `IsEquipped` bool 硬切移动树。

改动：

- 过渡链改成
  `Unequipped Locomotion --IsEquipped(t)--> Draw Weapon --exit .92--> Equipped Locomotion`
  `Equipped Locomotion --IsEquipped(f)--> Eqip_To_Uneqip --exit .92--> Unequipped Locomotion`
  （`Run_Uneqip` / `Run_Eqip` 各补一条）
- **没有新增 Animator 参数**，全靠原有 `IsEquipped` bool

**武器搬运**（`PlayerOutfit.cs`）：
- 收剑态 → 挂在 `SM_Item_Sword` 下
- 战斗态 → 挂在 `Hand_R` 下
- `BeginStanceTransition(bool toCombat)` 记录 `Time.time + duration * switchPoint`，到点后搬运
- 切换点（实测手最贴近挂点的时刻）：**拔剑 0.35、收剑 0.45**

**背挂姿态**：`Player.prefab` 的 `PlayerOutfit.sheathLocalEuler = (0, 0, **140**)` → 剑柄在右肩、剑身斜向左下（约 40°）。
> 扫描结论：绕挂点本地 Z 轴，180° = 竖直，130~145° = 30~45° 斜挂，90° = 水平横躺。

**背挂位置对齐**：按**包围盒中心**对齐到装饰剑的包围盒中心，并自动适配不同武器的 pivot 差异。
> ⚠️ 必须用 `Renderer.bounds`，**不能用 `localBounds × lossyScale`** —— 挂点带 115° 大旋转，
> 后者会把包围盒算大并把对齐点抬高 **0.53m**（武器飘到头顶）。

#### 我做过的分析（数据都在，可复用）

**剑身方向**（把武器本地 +Y 轴投影到角色的前/右/上三轴）：

| `equipmentEuler` | 前 | 右 | 上 | 结论 |
|---|---|---|---|---|
| `(-90,90,0)` 原始值 | **-0.01** | -0.65 | **0.76** | 剑**竖直向上**，杵在身前/脸前 |
| `(135,90,0)` 我试的 | **-0.50** | **0.84** | -0.22 | 剑**朝右后**（更糟）|
| `(0,90,0)` 我试的 | **0.72** | -0.53 | -0.45 | 剑**朝前下** |
| `(90,180,0)` 备选 | 0.70 | 0.54 | 0.47 | 剑朝前上 |

**剑柄握持**（用食指 `IndexFinger_01 1` 与拇指 `Thumb_01 1` 的中点当"手心"）：

- 手心相对 `Hand_R` 的局部坐标 = `(6.9554, 0.3859, -3.5891)`
- 原始配置下，剑柄中心**距手心 10.5cm**
- 令"武器本地 Y=0.1 处"（我假设的剑柄中心）落到手心，反推出
  `equipmentPosition = (6.96, -9.61, -3.59)`
- **9 把武器的拟合结果完全一致** → 说明这批 `SM_Wep_*` 的 pivot 位置统一

**我做的修改**：把 9 把武器统一改成
```
equipmentPosition: {x: 6.96, y: -9.61, z: -3.59}
equipmentEuler:    {x: 0,   y: 90,    z: 0}
```
离线渲染验证（8 个动画状态逐帧）"剑柄距手心 = 0.000"。**但用户反馈仍未解决，且这组值现在已被还原。**

#### 我的反思 —— 可能哪里错了

写在这里供接手者避坑，都是**未经证实的假设**，请自行验证：

1. **视角陷阱（已确认犯过一次）**：我第一次是在**侧视图**（相机在角色右侧）里扫角度选值，
   那个视角下"剑朝右"和"剑朝前"看起来一样 —— 结果把朝向改反了。
   **结论：判断朝向一定要把方向向量投影到 `pct.forward/right/up` 做数值判断，不要靠单一视角目测。**

2. **"手心"的定义可能不对**：我用食指+拇指中点是自创的，真实握持点可能应该是
   手掌骨骼、或者 `Hand_R` 原点沿某方向偏移。**建议先让用户标出"他认为剑柄应该在哪"。**

3. **"剑柄中心 = 武器本地 Y=0.1"是我假设的**，没有验证过这个模型的手柄实际在哪。
   建议用 `mesh.bounds` + 顶点分布分析出真实的剑柄/护手位置。

4. **`equipmentScale = 100` 与骨骼 `lossyScale = 0.01` 的换算链**可能存在我没想到的偏差，
   值得重新推一遍（`localPosition` 是"手部骨骼单位"，不是米）。

5. **离线渲染 ≠ 游戏内观感**：我全程用自建相机 + RenderTexture 验证，**和用户实际看到的第三人称视角差别很大**。
   建议**直接用游戏相机截图**（`ScreenCapture`）来确认，而不是离线渲染。

6. **没排除"用户看到的是别的武器"**：9 把武器参数一致，但用户可能装了某一把特定的。

### 4.3 背包换装：旧武器消失 ✅ 已修复

**根因**：`UIInventory.OnEquipmentDrop` / `OnSlotDoubleClick` 直接调 `PlayerOutfit.Equip(item)`，
而 `Equip` 内部只是把 `equippedWeaponItem` **覆盖**掉，旧物品**没有任何回收路径**。

**修法**（`UIInventory.cs`）：新增 `EquipAndReturnOld(item, sourceIndex)`，两条路径统一走它：

```
1. 先从背包移除新物品（腾出格子，避免背包满时旧装备被吞）
2. PlayerOutfit.Equip(item)；失败则把新物品放回原格
3. 把旧装备 TryAddItem 回背包
```

实测：装水晶长剑（背包 16 格）→ 再换巨剑 → `[4] 水晶长剑` 回到背包、巨剑移除，**数量仍 16** ✅
