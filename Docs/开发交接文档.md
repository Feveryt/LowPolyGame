## 2. 开发工作流（新 Agent 必读，含故障手册）

### 2.1 MCP 工具可用时的标准做法

已验证可用的工具与用法：
- `read_console`：诊断编译错误、日志确认（filter_text 过滤）
- `execute_code`：执行任意 C#（**CodeDom 编译器，C# 6 语法**：不要用 `out var`、switch 表达式、target-typed new；UnityEngine.AI 等命名空间的类型要用全限定名如 `UnityEngine.AI.NavMeshAgent`；`EditorSceneManager` 要写 `UnityEditor.SceneManagement.EditorSceneManager`）
- `manage_editor`：play / stop（进 Play 后等 5-15 秒场景加载完毕再调 execute_code，否则 "Timeout receiving Unity response"）
- `refresh_unity`：触发编译
- `manage_scene`：读活动场景、save
- `manage_camera`：screenshot（include_image=true 会返回图像，用于 UI 视觉验证，非常好用）
- `execute_menu_item`：执行编辑器菜单（实现"远程跑编辑脚本"）

### 2.2 MCP 故障手册（**长会话必遇到**）

| 症状 | 原因 | 处置 |
|---|---|---|
| `Tool not found: mcp__unity-mcp__...` | 长会话中工具通道退化（反复出现） | **让用户重启 ZCode 会话**，不要硬重试 |
| 调用发出去但没有结果/误发到别的工具 | 同上 | 同上 |
| `No Unity Editor instances found` | Unity 编辑器没开，或桥接状态文件缺失 | 确认 Unity 开着且项目已加载；必要时让用户重启 Unity |
| 进 Play 后首次调用超时 | 场景加载中 | sleep 10 秒重试 |
| `This cannot be used during play mode` | 在 Play 模式里做 MarkSceneDirty/SaveScene | 先 stop play 再操作；Play 中的场景修改退出时会被丢弃 |

## 4. 深坑记录（Landmines，踩过的都在这）

### 4.1 UIManager 面板注册表 scenePaths（背包"打不开"的根因）
`UIManager`（运行时从 `Resources/Prefabs/UI/UIManager.prefab` 自举）按 `panelEntries[].scenePaths` 决定在哪些场景激活面板。面板 GameObject 在 prefab 里就是 **inactive** 的，靠 `EnsurePanel → activateOnEnsure` 激活。
- **踩坑**：Inventory 条目只有 `[Demo 1.unity]` → TestAct 里面板永不激活 → **未激活物体的 Awake/OnEnable 从不运行** → UIInventory 没订阅 Tab 键，按键毫无反应
- **排查口诀**：任何"某面板/脚本没反应"，先查 ① UIManager 条目 scenePaths 是否含当前场景 ② 对象是否 active
- 已给 Settings/Inventory/PlayerResources/Dead/Dialogue 五个条目加 TestAct

### 4.2 命中盒缩放测量（百倍误差）
武器挂在 Hand_R 骨骼下（**骨骼 lossyScale ≈ 0.01**，武器 localScale=100 补偿）。测量武器包围盒时**必须用已挂载实例的世界 bounds**，再除以 Zone 的 lossyScale 换算回本地。曾经用"以固定缩放实例化采样"的方法，算出 3073×15803 的巨型判定盒（全图命中）。

### 4.3 ClearSlot 误删常驻命中盒
`PlayerOutfit.ClearSlot` 的清理条件曾写成销毁 `name == "WeaponHitboxZone" || name.StartsWith("SM_Wep")` —— 把常驻命中盒也删了 → **换装后玩家攻击完全无判定**。正确做法：只清理 `SM_Wep*` 前缀。**同类前缀清理逻辑都要小心误伤自带组件。**

### 4.4 装备物品的存档丢失
退出 Play/切后台会自动存档（`OnApplicationQuit` + `OnApplicationFocus(false)`），但旧存档结构不含装备字段 → 装备中的武器（已从背包移除）**凭空消失**。已通过 4.5 的字段扩展修复。**新增"从背包移除但存在于世界中"的状态时，务必同步存档结构。**

### 4.5 存档优先级（改场景初始物品没效果的坑）
`PlayerInventory.Initialize`：**如果存在属于当前场景的存档（sceneName 匹配），跳过 `initialItems`、直接恢复存档**。所以在 TestAct 里改 `initialItems` 不生效——因为 TestAct 有存档。要么改存档，要么清档（删 PlayerPrefs 键或走清档工具）。

### 4.6 uGUI Slider 结构
手搓 Slider 必须用标准结构：`Background` + `Fill Area`（内含 `Fill`）+ `Handle Slide Area`（内含 `Handle`），并给 `slider.fillRect`/`slider.handleRect` 赋值。**不要用负的 sizeDelta**（anchorMin==anchorMax 时 sizeDelta 就是实际尺寸，负值会让轨道完全不可见）。Fill Area 左右各内缩 9% 给手柄半径。

### 4.7 CinemachineImpulseListener 挂载位置
必须挂在 **CinemachineVirtualCamera** 上（挂在主相机会报错）。本项目挂在 Player Rig prefab 的 4 台虚拟相机上（两个场景实例自动继承）。

### 4.8 场景是二进制格式
Demo 1 和 TestAct 都被 Unity 存成二进制（Mixed 序列化）。**不能用文本 grep 检查场景内容**；要检查就开 Unity 用 execute_code 查询，或临时切 Force Text（切了记得别乱提交）。二进制文件在 git 里按二进制处理。

### 4.9 运行时 AddComponent 的序列化字段为空
例如 `EquipmentSlotView` 是运行时 AddComponent 的，其 `[SerializeField] icon` 为 null —— 必须提供 `BindIcon()` 之类的方法手动绑定子物体引用（或整套改用 prefab）。

### 4.10 DragonBoss 预制体结构
- Animator 在 **Model 子物体**上（FBX 实例自带），不在根；根上没有 Animator
- 模型宽 10.6 米（含翼展），受击胶囊 2.6×5.3 是按包围盒量出来的
- 素材包只有走路动画，`MoveSpeed` 参数驱动播放速度

### 4.11 玩家攻击在怪物控制器里的受击过渡
素材包控制器的受击过渡原本只从 Idle 出发 —— 攻击/移动中挨打不播受击动画（"受击延迟"的根因）。已给玩家+石头人全状态补充受击/死亡过渡（Tools/Combat/4）。

## 8. 与用户协作的习惯

- 用户说中文，喜欢直接给结论 + 明确的操作指引（"你只需要做 X"）
- 用户会在深夜挂机让 Agent 自主工作，白天验收。**大规模改动前先在文档里留说明**（本次工作的说明就在本文档）
- 用户在意：UI 风格统一（石质主题 StoneUiTheme）、功能可测（TestAct 场景）、"看得见"的效果（特效/音效/震动）
- 提交习惯：按功能拆 commit，中文 commit message（如 `feat：新增龙Boss与玩家防御机制`）
- 主目录下有 `开发日志.txt` 可参考用户自己的记录习惯
